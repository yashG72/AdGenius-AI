# Deployment (free tiers)

AdGenius runs live on free plans only. It's sized as a portfolio demo: one small server,
no paid services. This guide is the exact click-path.

```
 Browser ──► Vercel (Next.js frontend, free)
    │             │ sign-in route handlers
    ▼             ▼
 Render free web service: FastAPI + in-process jobs (TASK_MODE=inline)
    ├──► Neon            PostgreSQL (free, 0.5 GB)        - app data + agent checkpoints
    ├──► Qdrant Cloud    vector search (free, 1 GB)        - document chunks
    ├──► Gemini API      LLM + embeddings (free tier)
    └──► Tavily          web search (free, 1,000 credits/month)
 GitHub Actions ─► pings the API (keep-alive.yml) so it stays awake and Qdrant stays active
```

## How the free profile differs from local development

| Concern | Local (Phase 0–12) | Free deployment | Setting |
|---|---|---|---|
| Background jobs | Celery workers + Redis queue | Run inside the API process; unfinished jobs resume after a restart | `TASK_MODE=inline` |
| Redis | Required | Not used: caches and rate limits live in memory (one instance) | `REDIS_URL=` (empty) |
| Dense embeddings | Local model (~300 MB RAM) | Gemini embedding API (no model in RAM) | `EMBEDDING_PROVIDER=gemini` |
| Keyword (BM25) vectors | Local | Local (tiny, no neural model) | – |
| Uploaded files | Local disk | Render's disk is wiped on restart; files are only needed during indexing, so search keeps working, but "Reindex" of an old file fails (re-upload instead) | – |
| Upload limit | 25 MB | 5 MB | `MAX_UPLOAD_SIZE_MB=5` |

Nothing else changes: same code, same API, same UI.

**No Docker is needed:** Render runs the Python app directly, and Vercel builds Next.js
directly.

## 0. What you need

- The GitHub repo, with this code pushed.
- Your Gemini API key and Tavily API key (the same ones as in `backend/.env`).
- About 30 minutes.

## 1. Database: Neon

1. Sign up at <https://neon.tech> (GitHub login works). Create a project:
   - name `adgenius`
   - Postgres 17
   - region **Asia Pacific (Singapore)**, the same region as the API
2. On the dashboard, click **Connect**.
   - Turn **Connection pooling OFF.** The host must **not** contain `-pooler`. The agent
     checkpointer sets its schema through a startup option that the pooler rejects.
   - Copy the connection string. It looks like:
     ```
     postgresql://neondb_owner:PASSWORD@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
     ```
3. That string is your **`DATABASE_URL`**. Paste it exactly as Neon shows it: the app
   converts it for its async driver by itself (`postgresql+asyncpg://`, `ssl=require`).
   Tables are created automatically on the first deploy (`alembic upgrade head` runs
   before the server starts).

## 2. Vector database: Qdrant Cloud

1. Sign up at <https://cloud.qdrant.io>. Create a **Free** cluster in the region closest
   to Singapore.
2. Copy the **cluster endpoint** and add `:6333` (`https://xxxx.cloud.qdrant.io:6333`). This is **`QDRANT_URL`**.
   Free clusters aren't offered in Singapore; AWS Seoul is the closest region.
3. Under **API Keys**, create a key. This is **`QDRANT_API_KEY`**.

The collection is created on the first upload. Free clusters are suspended after a week
without use; the keep-alive workflow (step 5) prevents that.

## 3. API: Render

1. Sign up at <https://render.com> with GitHub.
2. Choose **New → Blueprint** and select this repository. Render reads
   [`render.yaml`](../render.yaml) and proposes the service **adgenius-api** (free plan,
   Singapore).
3. Fill in the secret values it asks for:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Neon's connection string from step 1, pasted as-is |
   | `QDRANT_URL` / `QDRANT_API_KEY` | from step 2 |
   | `GOOGLE_API_KEY` | your Gemini key |
   | `TAVILY_API_KEY` | your Tavily key |
   | `CORS_ORIGINS` | `["https://adgenius-ai.vercel.app"]`. Use the Vercel URL you'll create in step 4; you can correct it afterwards |

   `JWT_SECRET_KEY` is generated by Render automatically.
4. Click **Apply**.
   - The first build takes a few minutes (installing packages).
   - Watch the **Logs** until you see `Uvicorn running on http://0.0.0.0:...`.
5. Copy the service URL, e.g. `https://adgenius-api.onrender.com`. Check it:
   - `https://adgenius-api.onrender.com/api/v1/health` → `{"status":"ok",...}`
   - `https://adgenius-api.onrender.com/api/v1/health/ready` → `database` and `qdrant` both `ok`

## 4. Frontend: Vercel

1. Sign up at <https://vercel.com> with GitHub. Choose **Add New → Project** and import
   this repository.
2. Settings:
   - **Project name:** `adgenius-ai`, which gives `https://adgenius-ai.vercel.app`
   - **Root Directory:** `frontend`
   - **Framework preset:** Next.js (detected automatically)
   - **Environment variables:**

     | Key | Value |
     |---|---|
     | `NEXT_PUBLIC_API_URL` | your Render URL, e.g. `https://adgenius-api.onrender.com` |
     | `API_URL` | the same Render URL |
3. Click **Deploy**.
4. If the final Vercel URL differs from what you put in `CORS_ORIGINS`, update that
   variable in Render (**Environment** tab). Render redeploys automatically.

`NEXT_PUBLIC_API_URL` is baked into the build. If the API URL ever changes, redeploy the
frontend.

## 5. Keep-alive (GitHub Actions)

Go to the GitHub repo → **Settings → Secrets and variables → Actions → Variables** →
**New repository variable**: `API_URL` = your Render URL.

[`.github/workflows/keep-alive.yml`](../.github/workflows/keep-alive.yml) then runs on its
own schedule:
- **Every 14 min:** pings `/health`, so a recruiter never waits for a cold start. This uses
  about 730 of Render's 750 free hours a month.
- **Daily:** pings `/health/ready`, which queries Neon and the Qdrant collection, so the
  free Qdrant cluster is never suspended.

To check it once, open the Actions tab → keep-alive → **Run workflow**.

## 6. Smoke test the live site

1. Open the Vercel URL. If the API was asleep, the sign-in page shows "Waking up the demo
   server…" for up to a minute.
2. Register, create a workspace and a brand, then upload the files from
   [`samples/brewnest/`](../samples/brewnest/). All of them should reach **Indexed**.
3. Ask the knowledge base "How much caffeine is in Vanilla Oat?" → 140 mg, with a
   citation.
4. Create the campaign from `samples/brewnest/README.md`, approve a concept, and wait for
   **Completed** (about 3–5 minutes). Then download the PDF.

## Limits to know (free plans)

| Limit | Effect | What to do |
|---|---|---|
| Render: 512 MB RAM, 0.1 CPU | One campaign at a time (`INLINE_MAX_CONCURRENT_CAMPAIGNS=1`); others wait their turn | Fine for a demo |
| Render restarts or redeploys | Running jobs stop and **resume automatically** at startup from their last checkpoint | – |
| Gemini free tier: per-minute and per-day request caps | A busy day can hit the cap; runs then fail with a clear error and can be retried later | Keep the demo to a few runs a day |
| Tavily: 1,000 credits a month | About 6 credits per campaign; search results are cached | – |
| Neon: 0.5 GB storage | Thousands of campaigns' worth | – |
| GitHub pauses schedules after 60 days without repo activity | Keep-alive stops | Push any commit, or click "Enable workflow" |

## Updating the live site

Push to `main`. Render and Vercel both redeploy automatically, and database migrations
run at API startup.
